# Deadlock Coach — текущее состояние

Срез от 12 ноября 2026 года. Опубликованный релиз — **0.14.5**, тег `v0.14.5`, коммит `f45c182`. [Релиз](https://github.com/vitaliypisniy1-debug/deadlock-coach/releases/tag/v0.14.5). Ветка `main` дополнена пилотом реплеев (`c8f32db`) и подготовлена к выпуску **0.15.0** (метрика «смерти в одиночку», см. ниже). Пуш выполняется без перезаписи истории.

Это перечень реализаций, а не отчёт о сквозном тестировании всех функций. На Windows прошли все 59 тестов опубликованной базы. Команда `npm run dist` собрала NSIS и portable для x64 с Electron 33.4.11. На временном профиле запущен код из собранного `app.asar`: загрузилось главное окно, видны девять пунктов навигации и доступен мост `window.dc`. Вход Steam, реальный оверлей в матче, экспорт в игру и установка поверх прежней версии в этой задаче не повторялись.

12.11.2026, после переноса пилота, в этой рабочей папке дополнительно проверено без изображений (через протокол отладки CDP и журналы):

- `npm test` — 61 тест, все прошли.
- Запуск из исходников на изолированном профиле (`--user-data-dir` во временную папку): окно загрузилось, мост `window.dc` доступен, 9 пунктов навигации; `dc.replay` без матча возвращает читаемую ошибку, `dc.cancelReplay` возвращает `true`, `crash.log` не появился.
- С синтетическим матчем в профиле `dc.replay` дошёл до реального Deadlock API и вернул «Реплей этого матча пока недоступен в Deadlock API»; матч не удалён защитой личных данных.
- Пересобран `npm run dist`: в `app.asar` появился `replayAnalysis.js` и код запроса реплея (прежняя сборка 02:34 была без пилота). `latest.yml` и установщик совпадают по SHA-512 — автообновление пройдёт проверку.
- Запуск собранного `win-unpacked/Deadlock Coach.exe` на изолированном профиле: окно, мост, 9 разделов и отмена работают; разбор синтетического матча завершился читаемым сообщением о таймауте (сервис держал несуществующий матч в очереди), без падений. Успешный разбор на реальном реплее в окне собранной версии пока не подтверждён.

## 0.15.0 — «смерти в одиночку» и связка «эпизод → цель»

Порог откалиброван на трёх реальных матчах: командные смерти — ближайший живой союзник в пределах ~2 500 единиц карты, одиночные — 2 800–9 700 (9–30 с бега при 320 ед./с). Формат хранения матчей не менялся (`EXTRACT_V` остался 2), перекачка истории не нужна. У топ-матчей маршрутов нет — там метрика `null`, а не ноль.

Проверено 12.11.2026:

- `npm test` — 63 теста, все прошли (61 прежний + 2 новых: правило «смерти в одиночку» с покрытием `checked`, цель тренера из эпизода при малом числе игр).
- Модули на реальных матчах (127436345, 135815802, 135817652): правило срабатывает на 5 и 9 одиночных смертях с именами убийц, секундами бега до союзников и числом соперников; в «чистом» матче не срабатывает, но игра помечается проверяемой (ложного «нуля ошибок» нет); NaN/undefined в текстах нет.
- Запуск из исходников с CDP (реальный профиль, только чтение): 9 разделов открываются без ошибок консоли. На экране «Ошибки» цель «Не больше одной смерти в одиночку после 10:00» с эпизодами (основание: 13 из 29 проверяемых матчей, доля побед с замечанием 31% против 56% без). Нажатие «Отслеживать в тренере» создаёт главную цель в «Тренере» с кнопкой «Основание цели · 12:27» и «До начала цели: 60%»; обратный переход открывает эпизод «Смерть в одиночку — убил Drifter» с кругом на карте. Существующий план тренера не сломан (4 цели, проверки ✓/✕ работают).
- `npm run dist` — NSIS и portable 0.15.0 для x64 собраны локально.

Изменённые файлы: `src/core/deaths.js` (новый), `src/core/features.js` (поле `soloDeaths`), `src/core/leaks.js` (правило 4a `solo_deaths`, цель в профиле), `src/core/coach.js` (запись каталога, `field`, `focusEvidence`, план из одного эпизода), `src/main/sync.js` (валидация эпизода `solo_deaths`), `src/renderer/app.js` (кнопка «Отслеживать в тренере» для новой цели, toast ошибок валидации), `test/run.js`.

## Незавершённые изменения и ограничения

- Пилот «Разобрать реплей» опубликован в `main` на GitHub (коммит `c8f32db`, 12.11.2026). Рабочая папка совпадает с этой веткой: все 63 файла `src/`, `test/`, `tools/` и `build/` сверены по SHA-256 с исходной папкой пилота, версия `package.json` осталась 0.14.5, `fzstd` — чистый JavaScript без нативного кода, поэтому `app.asar.unpacked` в сборке нет и это нормально. Папка `../deadlock-coach-city` без Git-истории осталась как копия, базой выпуска не является. `package-lock.json` в Git не входит, как и раньше.
- В предыдущей сессии в пилоте прошёл 61 тест и сверились 31 событие смерти одного публичного реплея. Второй реплей API не нашёл.
- Свежесть истории зависит от покрытия Deadlock API. Недостающие события, расхождение часов и неполные данные могут мешать привязке к эпизоду. Интерпретация Rift и ящиков требует проверки на реплеях.
- Playwright, Vitest, ECharts, DuckDB и Sentry отсутствуют в манифесте релиза. Диагностика опирается на локальные журналы, существующие тесты и ручные проверки.
