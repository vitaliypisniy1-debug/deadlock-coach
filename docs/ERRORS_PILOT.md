# Пилот «Ошибок» на 10 000 матчей — 13.11.2026

Ветка `errors/audit`. Скрипты — [tools/errors-pilot](../tools/errors-pilot/README.md), нормы — `src/core/data/errorNorms.json`. Личных данных в документе нет: только агрегаты.

## Выборка

- 10 100 рейтинговых матчей deadlock-api за 11–13.11.2026 (сборка 6861, от 25 минут), случайно по хешу `match_id`; маршруты есть у всех 12 игроков каждого матча; 120 972 игрока-матча, у 119 518 известен ранг.
- Загрузка: ~0,32 с на матч, 0 ошибок и лимитов на метаданных; лимит есть только у SQL (2 запроса в минуту). Матч сырым ≈ 1,2 МБ, сжатым с маршрутами ≈ 162 КБ; 10 100 матчей ≈ 1,6 ГБ — хранить нельзя, храним агрегаты.
- Ранг игрока — из SQL `player_rank_initial_display_rank` (значок = уровень·10 + ступень). **Средний значок матча в метаданных новых рейтинговых матчей равен 0.**

## 1. Связь правил с победой («в лоб» ненадёжна)

Разница доли побед «с замечанием минус без» при сравнении игроков одного ранга (3 группы), числа смертей (6 групп) и длины матча (3 группы); 90% интервал — бутстреп по матчам.

| Правило | Срабатывает | Разница, п.п. [90% интервал] |
|---|---|---|
| Фарм при проигранной драке | 5 212 из 97 109 | −11,6 [−12,7; −10,1] |
| Смерть в одиночку (≥2) | 41 166 из 118 917 | −0,7 [−1,3; −0,1] |
| Размен на линии | 20 055 из 119 518 | +3,0 [+2,4; +3,7] |
| Потеря душ при смерти | 27 518 из 46 753 | +3,7 [+2,9; +4,6] |
| Тайминги карты | 86 380 из 119 518 | +2,2 [+1,9; +2,7] |
| Смерть с непотраченными душами | 37 451 из 116 257 | +5,8 [+5,5; +6,4] |
| Живучесть после серии смертей | 843 из 97 301 | +3,7 [+1,6; +6,9] |

Смерти в одиночку по числу (≥1…≥5): −1,2…−0,1 п.п., везде в пределах шума. По классам и мобильности героев: −2,0…+1,7. По рангам эффект одинаков. Доля одиночных смертей среди поздних, наоборот, даёт +7…+13 п.п. — артефакт: победившая команда давит в нескольких местах, а смертей у неё меньше.

Главное ограничение: **общее число смертей почти полностью определяет исход** (команда, умирающая на 7+ раз реже соперника, выигрывает 95%; на 7+ раз чаще — 5%). Поэтому поправка на смерти «съедает» эффект любого правила про смерти, а смерти — это и причина, и следствие проигрыша. Долю побед нельзя считать ценой ошибки.

## 2. Эпизодная оценка (что происходит дальше)

Исход — разность убитых соперников и убитых союзников за 75 секунд после события; сравнение при одинаковой обстановке (фаза игры, число живых союзников и соперников, ранг).

- **Смерть в одиночку.** 145 090 событий против 408 014 смертей рядом с союзником. Среднее за 75 с: −0,14 после одиночной смерти и −0,31 после смерти в драке; при одинаковой обстановке разница +0,14 [+0,13; +0,15]. Команда **не теряет больше**, чем после смерти в драке.
- **Драка (≥3 смертей после 10:00): союзник фармит вдали.** 32 534 команды-эпизода с таким союзником против 94 074 без. Итог драки при том же числе присутствующих: +0,035 [+0,010; +0,058]; при двух и более фармящих вдали +0,13 [+0,07; +0,17]. Исход драки **не хуже**. Прежняя связь «−12 п.п.» объясняется самой проигранной дракой (правило определяется проигрышем).
- **Линия.** Разрыв по душам к 10:00 (своя пара минус пара соперников) напрямую связан с победой на всех рангах: ≤ −1 500 → 33–36% побед; −1 500…−800 → 40–43%; −800…−300 → 44–45%; около нуля → 50%; +300…+800 → 55–56%; +800…+1 500 → 58–60%; > +1 500 → 64–68%. У игроков с замечанием «размены в пользу врага» средний разрыв с соперником по линии −883 души, у остальных +178.

## 3. Решения по правилам

| Правило | Статус | Почему |
|---|---|---|
| Размен на линии | **вывод** | цена измерена: разрыв по душам к 10:00 и монотонная связь с победой; в тексте — разрыв в душах и доля побед |
| Потеря душ при смерти | **вывод** | цена — сами потерянные души, факт из статистики; охват узкий (смерти должны быть отделимы по замерам) |
| Смерть в одиночку | наблюдение | после неё команда не теряет больше; связи с победой нет |
| Фарм при проигранной драке | наблюдение | исход драки не хуже при фармящем вдали союзнике |
| Тайминги карты | наблюдение | связь с победой слабая (3–5 п.п.), срабатывает в 7 из 10 игр |
| Смерть с непотраченными душами | наблюдение | оценка остатка — нижняя граница, связь с победой не найдена |
| Живучесть после серии смертей | наблюдение | срабатывает редко, цена не подтверждена, нужен реплей |
| Нет ответа на героя | наблюдение | статистика покупок топов, связь с победой 0 п.п. |

Наблюдения: уровень `info`, поле `status: 'observation'`, не попадают в «Главное сейчас», в цели тренера и в «главный повторяющийся совет» оверлея; в тексте — «Цена не подтверждена» и «Чего не хватает». Выводы идут первыми в профиле.

## 4. Нормы по герою и рангу

`errorNorms.json`: по каждому герою × группе рангов (1–5, 6–7, 8+) квантили (25, 50, 75, 90%) смертей в одиночку, эпизодов фарма при драке, смертей после 10:00, разрыва на линии к 10:00, потери душ за смерть и смертей до 10:00 (всего 180 ячеек, ≥60 игроков в ячейке; запасные варианты: герой → ранг → все). Порог «смерть в одиночку» теперь выше 3-го квартиля нормы героя и ранга (обычно >2), а не фиксированное «≥2». Для сравнения в тексте: «у игроков на {герой} твоего ранга обычно 1, в 3 играх из 4 — не больше 2».

## 5. Ранг игрока из `badge`

Во всех личных матчах владельца с 30.10.2026 (110 из 110) и во всех 10 100 матчах пилота `badge` = [0, 0]. Что ломалось:

- `overview.js`: средний ранг за 7 дней строился только по значку матча → для свежих игр `rank: null` («средний ранг твоих матчей» не показывался);
- `sync.js` (коуч): `tierOf` давал уровень 0 вместо «неизвестно» (в `gameLeaks` 0 отбрасывался, в новых нормах 0 стал бы «рангами 1–5»);
- у остальных игроков матча ранг из метаданных недоступен совсем — только SQL (`player_rank_initial_display_rank`).

Исправлено без изменения формата хранения: `src/core/rank.js` (`gameBadge`: значок команды, если > 0, иначе собственный `ranked_display_badge` из истории; `tierOfBadge(0)` → `null`), используется в `overview.js` и `sync.js`; в нормах ранг 0 = «неизвестен».

## 7. Рабочая роль игрока (автоматически)

Роль определяется по данным матча без ввода пользователя (`src/core/roles.js`, границы — перцентили 120 тысяч игроков в `errorNorms.json`, `roleCuts`). Признаки: доля урона команды, доля полученного урона, доля лечения, доля душ команды, участие в убийствах, доли душ от добивания, леса, героев, боссов и коробок, сборка (оружие / дух / живучесть), кто первым вступает в бой в драках (по маршрутам: контакт с героями не позже других участников своей команды).

- **Инициатор (передовая):** получено урона не меньше, чем у трети игроков рейтинга, и либо первым вступает в бой в половине драк и чаще, либо берёт много живучести.
- **Керри (урон):** доля урона в верхней трети.
- **Поддержка:** урон в нижних 40%, и либо много лечения, либо мало душ команды.
- **Универсал:** остальное — нет ярко выраженного стиля.

Проверка на реальных данных (120 972 игрока): роли совпадают с тем, как играются герои. Инициаторы чаще всего — Mo & Krill, Victor (75%), Billy, Abrams, Bebop; керри — Deadman Danny, Vindicta, Paradox, Pocket, Grey Talon, Lady Geist; поддержка — Nurse Harrow (84%), Rem (76%), Ivy. Общий состав: инициатор 24%, керри 24%, поддержка 19%, универсал 33%. Роль — это стиль игры в матче, а не класс героя: один и тот же герой часто играют по-разному (Haze: керри 32%, универсал 44%).

**Роль на герое** (`heroRoles`): по серии игр — главная роль, доля игр с ней («согласие») и доверие. Меньше 5 игр — «мало данных», роль не называется; согласие ≥ 70% и ≥ 10 игр — высокое; ≥ 50% — среднее; иначе низкое (роль меняется от игры к игре). Ответ `leaks()` содержит `roles`.

**Нормы по роли:** в `errorNorms.json` добавлены ячейки `role:<роль>|<ранг>`. Для смертей в одиночку и фарма при драке сравнение идёт с нормой роли игрока в этом матче, затем героя и ранга; в тексте и контексте замечаний сказано, что роль определена автоматически, и названы признаки. По данным нормы смертей в одиночку у ролей почти не отличаются (3-й квартиль 2 у всех), зато разрыв по душам на линии к 10:00 различается: медиана у керри +248, у поддержки −336.

Ограничения: роль в одном матче — приближение (первый вход в бой — по маршрутам с шагом 5 секунд, ничьи в пользу игрока). Личные роли владельца в Git не кладём: они считаются на его профиле скриптом по запросу.

## 6. Ограничения

- Наблюдательные данные: любой эффект — связь, не причина. Эпизодная оценка видит только убийства за 75 с; потеря душ, времени и карты в неё не входит.
- Выборка — два дня рейтинга одной сборки (6861). После обновления игры нормы и таблица `LANE_GAP_WIN` нужно пересчитать (`tools/errors-pilot`).
- Нормы по героям на малых ячейках (60–150 игроков) шумны; для героя без ячейки берётся ранг или вся выборка.
- Позиция в драке (передовая / вторая линия) не считалась отдельно; «первым в бой» — приближение по маршрутам с шагом 5 секунд.
- Не проверено на живом экране: появление ранга на главной после исправления (нужна история владельца из API; в тесте — синтетическая история).
