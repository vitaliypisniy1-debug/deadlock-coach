# Deadlock Coach — контекст проекта

Deadlock Coach — Windows-приложение для подготовки к игре, разбора матчей и тренировки конкретных навыков. Срез архитектуры основан на `main` и теге `v0.14.5`. Рабочие изменения и результаты проверок перечислены в [CURRENT_STATE.md](CURRENT_STATE.md).

| Часть | Где и как работает |
|---|---|
| Electron | `src/main/main.js` создаёт окно, оверлей и IPC, связывает Steam, синхронизацию и обновления. `src/main/preload.js` предоставляет интерфейсу ограниченный мост `window.dc`. |
| Интерфейс | `src/renderer/` содержит локальные HTML, CSS и JavaScript, SVG-графики и миникарту. React и Vite в релизном манифесте и коде интерфейса отсутствуют. Оверлей использует отдельное окно. |
| Матчи и советы | `src/core/` преобразует метаданные в компактные записи и рассчитывает экономику, сравнения, матчапы, пики, цели и повторяющиеся ошибки. Сохранённые маршруты дают возможность перейти к эпизоду на миникарте. Расчёты основаны на данных и правилах, вызовов языковой модели в релизной аналитике нет. |
| Внешние данные | `src/main/api.js` и `sync.js` связывают очередь, кэш и Deadlock API. История, метаданные, ладдер и справочники приходят отдельно. Доступность свежего матча зависит от сервиса. Есть работа с кэшем Steam. |
| Хранение | `src/main/store.js` управляет JSON, отдельными файлами матчей и `matches.pack`. Данные находятся под `app.getPath('userData')/data`. Есть поддержка старого каталога `%APPDATA%/deadlock-coach`. Личные матчи защищаются при очистке кэша. |
| Steam и оверлей | В коде есть OpenID и ручная привязка Steam ID. Ручной ввод выбирает профиль без подтверждения владения. Оверлей использует горячую клавишу, снимки экрана для распознавания и данные консольного журнала для отдельных фаз игры. |
| Сборка и выпуск | CommonJS, Electron `^33.2.1`, Node 20 в CI, `electron-builder@25.1.8`. `npm test` запускает `test/run.js`, `npm run dist` собирает NSIS и portable без публикации. `.github/workflows/release.yml` отвечает за Windows-сборку и релизы. Обновлятор проверяет SHA-256 перед запуском установщика. |

Поток личного разбора: история по Steam ID → метаданные матча → выжимка и кэш → сравнение и эпизоды → графики, таблицы и карта. Точные события, интервальные замеры и выводы из статистики имеют разную точность. Учитывай это в подсказках и тестах. [Deadlock API](https://api.deadlock-api.com/docs)

## Передача задачи между инструментами

1. **Codex App на Windows.** Открой корень клона или рабочей папки нужной ветки. Codex подхватит `AGENTS.md`. В новом чате назови задачу и попроси сверить ветку и документы перед изменениями. [Инструкции Codex](https://developers.openai.com/codex/guides/agents-md)
2. **Claude Code.** Запусти `claude` из корня того же клона для последовательной работы. Для параллельной работы используй другую ветку и рабочую папку. `CLAUDE.md` импортирует общие правила. Для внешнего поставщика укажи `ANTHROPIC_BASE_URL` и поддерживаемую поставщиком авторизацию локально, по его инструкции. Anthropic-совместимый шлюз должен поддерживать Messages API, потоковые ответы и вызовы инструментов. Если поставщик предлагает только OpenAI-совместимый API, нужен совместимый шлюз с переводом протокола. Конкретный поставщик в проекте не настроен и не проверен. [Настройка шлюза](https://code.claude.com/docs/en/llm-gateway-connect) · [Совместимость](https://code.claude.com/docs/en/llm-gateway-protocol)
3. **Claude Projects в браузере.** В Project Knowledge выбери GitHub, подключи репозиторий и нужные файлы: `AGENTS.md`, `CLAUDE.md`, три документа из `docs/` и затрагиваемые исходники. В Project Instructions попроси сначала прочитать эти файлы. После разрешённого push нажми **Sync** и проверь, что доступен нужный срез. Пока коммит только локальный или коннектор показывает другую ветку, передай проверенные документы вручную и укажи коммит и дату. Веб-проект не видит рабочую папку Windows и не получает локальный коммит автоматически. [GitHub в Claude Projects](https://support.claude.com/en/articles/10167454-use-the-github-integration)

Для передачи отправляй следующий блок в новый чат. Ссылку на PR добавляй, когда он существует.

```text
Задача и критерий готовности:
Ветка, коммит и рабочая папка (для локальной работы):
Что сделано:
Что проверено и с каким результатом:
Что осталось, включая незакоммиченные правки:
Следующий шаг:
```

GitHub служит общей точкой только для опубликованных коммитов. Локально один инструмент редактирует ветку за раз. При переходе проверь `git status --short --branch` и `git log -1 --oneline`. Перед получением опубликованных правок выполни `git fetch origin` и проверь расхождение. Для чистой ветки с настроенным upstream используй `git pull --ff-only`. Если ветки разошлись, изучи различия и согласуй их обычным Git-процессом с сохранением обеих версий. Коммить изменения задачи отдельно и публикуй только с разрешения владельца.
